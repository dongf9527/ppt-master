## 5. 问题分级

### P0（任务失败根因）

1. **双输入幻觉**。事后核伪：`projects/real/sources/` 下**既无 `公司模板.pptx` 也无 `需求.md`**，只有模型自建工作区与空 exports。源件大概率自造（冒烟已现形同行为），材料百分百自拟。工作流 §2 GATE 原文："a bare topic without facts is not enough — **ask for material**"。违反后直接后果：要求的 5 页中"数据页（用材料里的数字）"整个消失，实际输出按模板 6 页骨架填空。
2. **指令结构不服从**。要求 5 页（封面/背景 2 要点/方案 3 要点/数据/结尾），实际产出按模板 6 页逐页填，背景变 3 条、方案拆 3 页——模板骨架反客为主。
3. **备注机制幻觉**。全文检索同版本仓库：管线中**不存在** `<svg:data type="audio/remark">` 机制；真实机制是 `notes/<页名>.md` 文件（`svg_to_pptx` 的 discovery/builder 走 notesSlide XML）。模型嵌入 SVG 的 6 段备注**注定全部丢失**，且塞在 `</svg>` 之后的非法片段正是后续 XML 解析连锁崩溃的祸根。

### P1（过程失控）

4. **越权修改管线源码**：`template_structure.py`（+39 行 `_NSPACED_PREFIXES` 补丁，日志可见）与 `animation_config.py`（日志截断段之外，全文检索无痕迹）。
5. **非原子编辑自毁现场**：整文件重写产生重复嵌套 `<g>`、根元素闭合后续写内容；随后误诊为 namespace 未注册，绕查 BOM/lxml/ElementTree 源码。
6. **路线混杂**：在 Edit Native 工作区伪造 `spec_lock.md`（"Validated ✓"字样）、手工拼装 `svg_output/` 子目录、试错旗标组合；工作区命名 `company-template-workspace` 不符 `<stem>_pptx_to_svg` 规范，疑为手工拼装而非管线产物。

## 6. 根因判定

- **部署层无责**：65.5k 窗口校准、三档模型映射、四层验收结论全部仍然有效，本次无任何环境报错。
- **边界所在**：9B 级模型的长程编排能力——保持页面规划不漂移、克制地原子编辑、缺材料时停下来问人、不碰管线源码。这些是 Edit Native PPTX 默认执行者（旗舰模型）的素养，不是部署能补的。

## 8. 经验与改进（已回填学习路径 v1.2）

1. **先验输入再开会话**：会话前 `ls projects/real/sources/` 眼见为实；提示词首行加"任一文件缺失立即停下问我，禁止代写"。
2. **一页一会话**：5 页任务拆 5 轮，每轮 `/clear`——对应部署方案 8.2 的 autocompact 经济账，9B 无整卷吞吐余量。
3. **保留确认关卡**：首轮只要"页面规划表 + 每页材料来源对照"，人工点头后再动 SVG；**不要**在提示词里写"不用跟我确认"。
4. **三条铁律**进提示词：禁代写材料／备注一律写 `notes/slide_XX.md`／禁改 `skills/` 下任何脚本。
5. **显存若有余量优先升档模型**（部署方案 8.1：KV cache 仅约 1 GiB），指令遵循收益大于提示词技巧。
